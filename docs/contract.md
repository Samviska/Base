# 数据契约

> **全项目最核心的文档。** 所有模块只通过契约通信。
> 碰数据结构前**必读**；要改契约前必读第 8 节。
> 本文件描述数据的**逻辑结构**，与它存放在什么格式的文件里无关（见 [modules/storage.md](modules/storage.md)）。

---

## 1. 设计原则

- 各环节只通过契约通信，**不传递语言内部的运行时对象**。
- **带版本号**；破坏性变更必须提升主版本并提供迁移说明。
- **自描述**：序列名、单位、轴描述都写在数据里，不靠外部约定。
- **契约与存储格式分离**：逻辑结构与物理文件格式是两件事。
- **未知字段必须原样保留**：读写过程中不认识的字段不得丢弃，否则扩展区形同虚设。

---

## 2. 顶层结构

```json
{
  "schema_version": "1.0",
  "meta": { },
  "series": [ ],
  "annotations": [ ]
}
```

---

## 3. meta

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `schema_version` | 是 | 契约版本号 |
| `source` | 是 | 数据来源：文件名或设备标识 |
| `extractor` | 是 | 产出者标识，格式 `插件名@版本` |
| `sample_count` | 否 | 总点数 |
| `notes` | 否 | 提取过程中的特殊处理记录（例如时钟跳变是如何处理的） |

---

## 4. series 与轴描述

### 4.1 series

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name` | 是 | 序列名，界面显示与引用都用它 |
| `unit` | 是 | 单位；无量纲写 `"1"` |
| `x` | 是 | 轴描述 + 数据（见 4.2） |
| `y` | 是 | 数据（见 4.3） |

### 4.2 x 轴描述（**开放式**）

x 轴类型**不由核心写死一组枚举**，而由**数据源声明其行为属性**。分三层：

| 层 | 内容 | 谁必须理解 |
| --- | --- | --- |
| **最小语义集** | `kind` + `scale` | 核心与**所有**渲染器 |
| **描述信息** | 单位、显示名、刻度格式、基准、是否单调 | 渲染器按需使用，**可忽略** |
| **扩展区** | `extensions` | 核心与通用渲染器**都不理解**，只透传 |

#### kind：核心定义的四类

| kind | 含义 | 渲染行为 |
| --- | --- | --- |
| `numeric` | 连续数值 | 按值映射到位置 |
| `sequence` | 等间隔序号 | 同 numeric，刻度显示为整数序号 |
| `time` | 时间（数值毫秒） | 同 numeric，刻度按时间偏移格式化 |
| `categorical` | 分类（字符串标签） | **等宽分布，不按值映射**（柱状图常用） |

#### scale：映射方式

| scale | 含义 |
| --- | --- |
| `linear` | 线性（默认） |
| `log` | 对数（数据动态范围大时用） |

#### 字段清单

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `kind` | 是 | 见上表 |
| `data` | 是 | 数据数组 |
| `scale` | 否 | 默认 `linear` |
| `unit` | 否 | 如 `"ms"`、`"Hz"` |
| `origin` | `kind: time` 时必填 | `epoch` / `start` / 具体数值，见 §6 |
| `display_name` | 否 | 界面显示名 |
| `tick_format` | 否 | 刻度格式建议 |
| `monotonic` | 否 | 是否单调递增（性能优化依据） |
| `numeric_values` | 声明未知 `kind` 时必填 | 这串值能否按数值处理 |
| `extensions` | 否 | 插件自定义元信息，核心只透传 |

#### 未知类型的处理规则（硬性）

1. 数据源**可以**声明核心不认识的 `kind`，但此时**必须同时声明 `numeric_values`**。
2. 渲染器遇到不认识的 `kind`：**降级为 numeric 渲染，并在界面明确标注"该轴以数值方式显示"**。
3. **绝不崩溃，绝不静默。** 静默降级会让人误判图形含义。
4. 校验器：`scale` 等核心属性必须是已知值（非法值直接拒绝）；`kind` **允许未知**，只做结构校验。

#### 为什么不能更自由

渲染器不认识的东西画不出来，这是信息论约束，不是保守。给类型起新名字不产生价值：

| 声明 | 结果 |
| --- | --- |
| `kind: "三轴合成加速度"` | 渲染器不认识 → 只能当普通数值轴画，**没得到任何好处** |
| `kind: numeric, unit: "m/s²", scale: linear` | 立刻画对，还能显示单位 |

真正有价值的扩展是把变化放进**行为属性的组合**：对数轴、分类轴、倒置轴、自定义刻度格式、自定义基准点。

### 4.3 y

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `data` | 是 | 与 `x.data` 等长的数值数组 |
| `unit` | 否 | 与 `series.unit` 不同时才需要 |

## 5. annotations

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `series` | 是 | 绑定到哪个序列（按 `name`） |
| `kind` | 是 | `point` / `range` / `text` |
| `x` | `point`、`range` 必填 | 位置或区间 |
| `label` | 否 | 显示文字 |
| `note` | 否 | 详细备注 |

注解与序列绑定、随数据一起存储，**必须可持久化与回读**（见 [modules/core.md](modules/core.md) 的会话部分）。

## 6. 时间表示

**决定：时间轴一律用"毫秒"这一种数值表示。不使用 ISO 8601 等文本时间格式，界面也不显示日历时间。**

依据：分析数据只看波形，不看日历时间。收益是数值可直接参与运算与绘制、体积小、比较排序快，
且彻底绕开时区与格式解析这些用不上的环节。

### origin：基准点

| origin | 含义 |
| --- | --- |
| `epoch` | 绝对时间（1970-01-01 UTC 起的毫秒） |
| `start` | 相对数据起点（第 0 毫秒 = 第一条数据） |
| 具体数值 | 相对某个给定时刻的毫秒 |

**刻度显示建议**：显示成**相对基准的偏移**（如 `+12.5s`）。
定位"尖峰出现在第几秒"时，这比绝对时间更好用。

### 必须处理的三个坑

1. **精度**：毫秒 / 微秒必须声明。嵌入式日志常见微秒或更高精度，若高于毫秒须在描述中说明。
2. **时钟跳变或回绕**（设备重置）：数据源插件必须显式处理，并把处理方式记入 `meta.notes`。
   **不得静默产生一条乱序的 x 轴**——那会让整张图失去意义。
3. **只有相对上电时间的日志**：直接用 `origin: start` + 数值毫秒，**不要硬凑绝对时间**。

## 7. 其余强制规定

| 事项 | 规定 |
| --- | --- |
| 缺失值 | 统一用 `null`，**禁止**用 `0`、`-1`、空串代替 |
| 多序列 | `series` 支持任意条；多条可共享同一 x 轴 |
| 单位 | 每个序列必须带 `unit`，无量纲写 `"1"` |
| 浮点精度 | 必须声明（避免微小的传感器变化被四舍五入抹平） |
| 未知字段 | 读写往返后必须**原样保留** |

---

## 8. 校验

- 提供**独立于界面**的校验器，可对任意数据判定：是否合规、违规字段路径、违规原因。
- 必须能**被自动化调用**（供测试与插件自检）。
- **强度分层**：核心属性严格校验（可拒绝非法值），扩展属性只做结构校验。

---

## 9. 版本与变更流程

1. 契约带 `schema_version`；破坏性变更必须提升主版本并提供迁移说明。
2. 变更时必须**同时**更新：
   - 本文件
   - 校验器
   - 受影响的模块文档
   - `DEVLOG.md`（标注影响面与是否需要迁移）
3. `contract/` 目录下放语言中立的权威定义与示例数据，作为跨语言的唯一依据。
