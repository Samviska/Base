# 操作手册

> `modules/` 讲"**某模块是什么、受什么规则约束**"；`guides/` 讲"**怎么做某一件事**"。
> 本页列出待建的手册与它们的写法要求。

---

## 已建成

| 文件 | 解决什么 |
| --- | --- |
| `kickoff.md` | **项目开发提示词**：要做什么、技术方案、不可违反的约束、模块地图、分六批的开发计划 |
| `framework-test.md` | 验证这套文档与规则在全新会话中是否还能用（[acceptance.md](../acceptance.md) 的 S3 验收前半段） |

## 一份合格的手册必须包含

1. **适用场景**：什么时候该用它
2. **前置条件**：先读哪份文档、需要哪些文件已存在
3. **完整步骤**：从零到能跑
4. **可直接运行的示例**：不是伪代码，是最小可用版本
5. **验证方式**：怎么确认做对了（可执行的检查）
6. **常见错误**：做错时的现象与纠正

---

## 写作要求

- 步骤必须**可照做**，不能是"配置一下即可"这类含糊表述。
- 示例必须**能直接跑起来**。
- 需要复制模板时，指明模板文件的**确切路径**。
