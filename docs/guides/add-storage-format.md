# 怎么加一种存储格式

> **状态**：待建。前置：先读 [modules/storage.md](../modules/storage.md)。

---

## 适用场景

JSON 撑不住了（加载慢、体积大），需要接入 SQLite、JSON Lines、Parquet 等格式。

> **触发条件**：实测发现单份数据的加载时间或文件体积超出可接受范围。
> **不要提前做**——只有一种实现时，格式探测是空转。

## 前置条件

- 已读 [modules/storage.md](../modules/storage.md)
- 已确定新格式的**性能特征**与**可读性代价**，并写入 [DECISIONS.md](../DECISIONS.md)

## 步骤（待补全）

1. 实现同一套接口：`open_source` / `meta` / `series_info` / `read_range` / `read_all` / `write` / `annotations`
2. 在格式表里登记一行
3. 补探测规则（若有确定的文件头特征）
4. 加交叉一致性测试（同一数据两种格式，读出来的结果必须相同）

## 验证方式（待补全）

- 上层代码与**所有插件零改动**即可使用新格式
- 同一份数据用两种格式存储后，读出的结果逐字段一致
- `read_range` 在新格式下是**真正的范围查询**，而非全读后切片

## 常见错误

| 现象 | 原因 |
| --- | --- |
| 上层代码被迫改动 | 接口里混入了格式相关的东西 |
| 未知字段消失 | 读写往返没有逐字段比对 |
| 探测误判 | 只按扩展名判断，未做内容探测 |
