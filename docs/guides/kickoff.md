# 开工提示词（新会话从这里开始）

> **用法**：新会话的第一条消息只发一句 ——
> `读 docs/guides/kickoff.md 并按其开工`
>
> 本文件负责「起步 + 排期」。技术细节与规则一律指向 `docs/` 下的权威文档，**不在这里重复**，
> 避免同一件事出现两个说法。

---

## 1. 要做什么

面向**嵌入式传感器日志**的分析绘图应用：**提取 → 滤波 → 绘图**。

| 环节 | 做什么 | 在哪 |
| --- | --- | --- |
| 提取 | 各种格式的设备日志 → 统一的契约数据 | 后端 |
| 滤波 | 全量数据 → 全量数据（可组合的处理链） | 后端 |
| 聚合 | 全量数据 + 视口 → 绘制数据（像素列 min/max） | 后端 |
| 绘图 | 绘制数据 → 画布，可缩放、平移、标记 | 前端 |

**核心不是"画图"，是让 AI 能持续维护与扩展**：核心稳定、契约固定、能力靠插件增长。

### 它要解决什么

| 现状 | 目标 |
| --- | --- |
| 手工把数据贴进 Excel 逐段画 | 丢进日志，几分钟看到曲线 |
| AI 生成的是单文件脚本，没有模块边界 | 分层工程，边界由契约固定 |
| 换个数据源就得让 AI 重新生成一遍 | **只新增一个插件文件，核心零改动** |
| 维护依赖聊天上下文，换会话就接不上 | 结论全部落在仓库文档里 |
| 交付物是打包的二进制或一个大 `.py` | 交付**完整可读的工程结构** |

## 2. 怎么做的底线

技术栈：Python 后端 + Vue 3（组合式 API）前端 + WebSocket + Canvas 2D。

**五条硬规则**——违反会返工，不是风格问题：

1. **渲染器接口不得引用 Vue**，只认「契约数据 + 一个挂载容器」。
   绑了框架，所有渲染插件（含第三方）作废。
2. **滤波在聚合之前，且都作用于全量数据**。顺序反了结果**直接是错的**，不是慢。
3. **禁止为显示流畅做抽样**。用像素列 min/max——抽样会抹掉尖峰，而问题就在尖峰上。
4. **前端永远拿不到全量数据**。跨进程接口只暴露「视口 + 分辨率」，靠结构保证，不靠约定。
5. **缺失值统一用 `null`**，禁止用 `0` / `-1` 顶替，否则波形出现假数据。

## 4. 开发顺序

**每批都必须能独立验证。** 不要一次写完再调试——那样出错时不知道是哪一层的问题。

### 第 1 批 契约校验器

| | |
| --- | --- |
| 位置 | `backend/contract/` |
| 依据 | `contract/schema/dataset.schema.json`、[modules/contract.md](../modules/contract.md) |
| 接口 | `validate(data) -> 校验结果`，结果**必须带违规字段路径与原因** |
| 依赖 | 只有 `jsonschema`（已在 `requirements.txt`） |
| 验证 | 跑 `contract/examples/` 下 4 份示例：`example-basic.json` 通过；3 份 `invalid-*` 被拒绝，且给出字段路径 |

**这一批不依赖任何其它模块，可以立刻开始。**

### 第 2 批 数据源与存储

| | |
| --- | --- |
| 位置 | `backend/sources/`、`backend/storage/` |
| 依据 | [modules/source.md](../modules/source.md)、[modules/storage.md](../modules/storage.md) |
| 内容 | 插件接口 + 目录扫描 + manifest 注册 + **异常隔离**；JSON 存储实现（接口按"按 x 范围读取"定义） |
| 验证 | 一份真实日志 → 契约数据 → 通过校验器；存盘再读回，字段一致 |

> **开工前要先确认你的日志是什么格式。**

### 第 3 批 滤波与聚合

| | |
| --- | --- |
| 位置 | `backend/filters/`、`backend/aggregate/` |
| 依据 | [modules/filter.md](../modules/filter.md)、[modules/aggregate.md](../modules/aggregate.md) |
| 内容 | 处理链接口 + 一个示例滤波插件；视口裁剪 + 像素列 min/max |
| 验证 | 点数超过分辨率 → 返回 min/max 对；未超过 → 返回原始点且 `ymin[i] == ymax[i]` |

### 第 4 批 核心与通信

| | |
| --- | --- |
| 位置 | `backend/core/`、`backend/server/` |
| 依据 | [modules/core.md](../modules/core.md)、[messages.md](../messages.md) |
| 内容 | 编排与缓存失效；WebSocket 服务与消息分发，先做 `M1`、`M2`、`M3`、`M6` |
| 验证 | 用 WebSocket 客户端跑通「打开文件 → 请求视口数据」 |

### 第 5 批 前端最小闭环

| | |
| --- | --- |
| 位置 | `frontend/` |
| 依据 | [ARCHITECTURE.md](../ARCHITECTURE.md) §5、[protocol.md](../protocol.md) §4 |
| 内容 | Vue 3 + Vite 骨架；通信客户端（**按帧节流 + 代次作废**）；Canvas 折线图；最少的面板 |
| 验证 | 选文件 → 看到波形 → 缩放平移不卡 |

### 第 6 批 补齐

标注、滤波链界面、柱状图、会话保存。对照 [acceptance.md](../acceptance.md) §6 的验收清单逐条做。

## 5. 提交

```powershell
python scripts/commit.py -m "契约: 实现校验器" --push
```

脚本会自动递增版本号、跑检查、提交并推送。
**不要直接 `git commit`** —— 版本号没递增会被钩子拒绝。

提交前必须：

1. 更新受影响的模块文档（`docs/modules/` 下）
2. 在 [DEVLOG.md](../DEVLOG.md) **最上面**追加一条

---

## 6. 边界

- 开发期**不需要打包**，也不要引入"必须手动构建才能看到效果"的做法。
- 新功能优先以**插件**形式实现；改核心必须给出书面理由。
- 拿不准就**先问**，不要猜着往下写。
- 契约要变（改数据结构）→ 先读 [contract.md](../contract.md) §9 的变更流程。
