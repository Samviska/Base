## 一、这是什么项目

面向**嵌入式传感器日志**的分析绘图应用。

```
设备日志 ──①提取──> 契约数据（全量） ──②滤波──> ──③聚合──> 绘制数据 ──④绘图──> 画布
           后端                      后端        后端         前端
```

**一句话**：把设备日志丢进来，几分钟内在浏览器里看到可交互的波形。

**核心不是"画图"，是让 AI 能持续维护与扩展**：核心稳定、契约固定、能力靠插件增长。

### 需求从哪来

| 现状 | 这个项目要变成 |
| --- | --- |
| 手工把数据贴进 Excel，一格一格画 | 丢进日志，选数据源插件，出图 |
| AI 给的是单文件脚本，改一处全崩 | 分层工程，边界由契约固定 |
| 换个数据源就得让 AI 重新生成一遍 | **新增一个插件文件，核心零改动** |
| 维护靠聊天记录，换个会话就接不上 | 结论全部落在仓库文档里 |
| 交付物是打包的 exe 或一个大 `.py` | 交付**完整可读的工程结构** |

使用者是**嵌入式开发者**，熟悉 C，对其它语言与框架不熟悉。
因此**扩展面必须极窄**——他只需要做两件事：把日志丢进来、让 AI 写一个新插件。

## 二、技术方案

| 层 | 选型 |
| --- | --- |
| 后端 | Python 3.11+ |
| 前端 | Vue 3（**只用组合式 API**）+ Vite |
| 前端语言 | JavaScript + JSDoc（**不引入 TypeScript 编译**） |
| 通信 | 单条 WebSocket + JSON 信封；HTTP 只用于加载页面 |
| 绘图 | Canvas 2D（**接口不绑定绘图技术**，将来可整块换 WebGL） |
| 契约 | JSON Schema draft 2020-12，放 `contract/schema/` |
| 存储 | V1 用 JSON；接口按"按 x 范围读取"定义，与格式解耦 |

**为什么前后端分离**：让契约成为**进程边界与语言边界**。
"把提取逻辑写进绘图代码"这种事，在结构上就不可能发生——这比写在规范里要求自觉可靠得多。

### 数据流的三条纪律

1. **提取、滤波、聚合全在后端**，前端只负责画。
2. **前端拿不到全量数据**：跨进程接口只暴露「视口范围 + 目标分辨率」，
   靠接口里**没有那个选项**来保证，不靠约定。
3. **滤波必须在聚合之前，且作用于全量数据**。

## 三、不可违反的约束

违反这些会返工或让设计作废，不是风格问题。

| # | 约束 | 违反的后果 |
| --- | --- | --- |
| 1 | 渲染器**接口**不得引用 Vue，只认「契约数据 + 一个挂载容器」 | 换框架时所有渲染插件（含第三方）作废 |
| 2 | 滤波在聚合**之前**，且都作用于**全量数据** | 结果**直接是错的**，不是慢 |
| 3 | **禁止为显示流畅做抽样**，用像素列 min/max | 抽样抹掉尖峰，而问题就在尖峰上 |
| 4 | 前端**永远拿不到全量数据** | 分层失效，滤波会算错 |
| 5 | 缺失值统一用 `null`，禁止用 `0` / `-1` 顶替 | 波形出现假数据 |
| 6 | 读写时**不得丢弃契约不认识的字段** | 插件的 `extensions` 静默消失 |
| 7 | 存储**接口名里不带格式**（不叫 `load_json`） | 加格式时要改所有调用点 |
| 8 | 开发期**不打包**，开发循环必须是「改代码 → 运行 → 看结果」 | 迭代速度被毁掉 |

## 四、模块地图

每个模块的接口、硬规则、已知的坑在它自己的文档里。

| 模块 | 职责 | 代码位置 | 文档 |
| --- | --- | --- | --- |
| 契约 | 数据长什么样 + 校验 | `contract/`、`backend/contract/` | `docs/modules/contract.md` |
| 数据源 | 日志 → 契约数据 | `backend/sources/` | `docs/modules/source.md` |
| 滤波 | 全量 → 全量 | `backend/filters/` | `docs/modules/filter.md` |
| 聚合 | 全量 + 视口 → 绘制数据 | `backend/aggregate/` | `docs/modules/aggregate.md` |
| 存储 | 契约数据的读写 | `backend/storage/` | `docs/modules/storage.md` |
| 后端核心 | 编排、会话、缓存失效 | `backend/core/` | `docs/modules/core.md` |
| 通信服务 | WebSocket 服务端 | `backend/server/` | `docs/modules/server.md` |
| 通信客户端 | 前端消息收发与配对 | `frontend/api/` | `docs/modules/api-client.md` |
| 渲染器 | 绘制数据 → 画布 | `frontend/renderers/` | `docs/modules/renderer.md` |
| UI 外壳 | 面板、控件、状态提示 | `frontend/ui/` | `docs/modules/ui-shell.md` |

**依赖方向单向**：契约不依赖任何人 → 插件只依赖契约 → 核心只认识契约，不认识具体插件。

## 五、开发计划

**分六批。每批独立完成、独立提交、独立可用。**
不要一次写完再调试——那样出错时不知道是哪一层的问题。

### 第 1 批 契约校验器

| | |
| --- | --- |
| 目标 | 把契约从"文档里的定义"变成"能执行的校验器" |
| 位置 | `backend/contract/` |
| 依据 | `contract/schema/dataset.schema.json`、`docs/modules/contract.md` |
| 交付 | `validate(data) -> 校验结果`，结果**必须带违规字段路径与原因** |
| 完成标志 | `contract/examples/` 下 4 份示例：1 份通过、3 份被拒绝且指出出错字段 |

依赖只有 `jsonschema`（已在 `requirements.txt`）。**这一批不依赖任何其它模块。**

### 第 2 批 数据源与存储

| | |
| --- | --- |
| 目标 | 把真实日志读进来，并且能存能读 |
| 位置 | `backend/sources/`、`backend/storage/` |
| 交付 | 插件接口 + 目录扫描 + manifest 注册 + **异常隔离**；JSON 存储实现 |
| 完成标志 | 一份真实日志 → 契约数据 → 通过校验器；存盘再读回，字段一致 |

> 开工前需确认**日志的实际格式**。

### 第 3 批 滤波与聚合

| | |
| --- | --- |
| 目标 | 从全量数据算出"该画哪些点" |
| 位置 | `backend/filters/`、`backend/aggregate/` |
| 交付 | 处理链接口 + 一个示例滤波插件；视口裁剪 + 像素列 min/max |
| 完成标志 | 点数超过分辨率 → 返回 min/max 对；未超过 → 返回原始点且 `ymin[i] == ymax[i]` |

### 第 4 批 核心与通信

| | |
| --- | --- |
| 目标 | 让前端能拿到绘制数据 |
| 位置 | `backend/core/`、`backend/server/` |
| 交付 | 编排与缓存失效；WebSocket 服务与消息分发，先做 `M1`、`M2`、`M3`、`M6` |
| 完成标志 | 用 WebSocket 客户端跑通「打开文件 → 请求某个视口的数据」 |

### 第 5 批 前端最小闭环

| | |
| --- | --- |
| 目标 | 看到图 |
| 位置 | `frontend/` |
| 交付 | Vue 3 + Vite 骨架；通信客户端（**按帧节流 + 代次作废**）；Canvas 折线图；最少的面板 |
| 完成标志 | 选文件 → 看到波形 → 缩放平移不卡 |

### 第 6 批 补齐

标注、滤波链界面、柱状图、会话保存。
对照 `docs/acceptance.md` §6 的验收清单逐条做。

## 六、开发规范

**代码注释**：只写代码表达不了的信息——意图、约束、坑、外部依赖。
不复述字段名，不写「本函数用于……」。

**文档**：改了某个模块就更新 `docs/modules/` 下对应的文档；
每次提交在 `docs/DEVLOG.md` 最上面追加一条（格式见该文件顶部）。

**提交**：

```powershell
python scripts/commit.py -m "契约: 实现校验器" --push
```

脚本会自动递增版本号、跑检查、提交并推送。**不要直接 `git commit`**——会被钩子拒绝。

**契约变更**（改数据结构）走 `docs/contract.md` §9 的流程，不能顺手改。
