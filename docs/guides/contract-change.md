# 怎么改契约

> **状态**：待建。前置：必读 [contract.md](../contract.md)（全文）与 [modules/contract.md](../modules/contract.md)。

---

## 适用场景

需要增删字段、修改轴描述、改变时间表示、调整校验规则。

**注意**：改契约是**破坏性最强的改动**，因为它影响所有模块。动手前先确认真的必要。

## 判定：这次改动是不是破坏性的

| 改动 | 是否破坏性 | 版本处理 |
| --- | --- | --- |
| 新增**可选**字段 | 否 | 次版本 |
| 往扩展区（`extensions`）加内容 | 否 | 不升版本 |
| 新增必填字段 | **是** | 主版本 + 迁移说明 |
| 改字段语义、删字段、改类型 | **是** | 主版本 + 迁移说明 |

## 步骤（待补全）

**必须按顺序做完，不允许只做前两步：**

1. 提升 `schema_version`
2. 更新 `contract/schema/` 的定义
3. 更新校验器
4. 更新 [docs/contract.md](../contract.md)
5. 更新 `contract/examples/`（含扩展字段的往返用例）
6. 检查受影响的模块文档并更新
7. 写 [DEVLOG.md](../DEVLOG.md)，**必须写清影响面与是否需要迁移**

## 验证方式（待补全）

- 校验器能接受新的合法数据，并**拒绝**旧的非法数据
- 往返测试通过：读进来再写出去，**未知字段一个不丢**
- 受影响的模块全部能跑通

## 常见错误

| 现象 | 原因 |
| --- | --- |
| 文档说合法、校验器拒绝 | 步骤 3 或 4 漏做 |
| 插件报错 | 未通知受影响的插件作者，或未提供迁移方式 |
| 扩展字段丢失 | 序列化路径上有一处没有透传未知字段 |
