## 架构形态

### D1 前后端分离：Web 前端 + Python 后端，契约作为物理边界

**决策**：前端用浏览器技术栈，后端用 Python，两者以 JSON 契约作为**进程边界**。

**理由**：

- 渲染能力上限最高（Canvas / WebGL 是通用绘制 API）；
- Python 侧"插件就是一个 `.py` 文件丢进目录"是天然成立的，不需要自造脚本引擎；
- 解析设备日志这类代码，AI 生成 Python 的可靠度最高；
- 契约成为进程 / 语言边界，**"把提取逻辑写进绘图代码"在结构上不可能**。

**代价**：两套运行时；打包需要方案。缓解方式见 D10。

### D2 前端用 Vue 3 + Vite，不用原生 HTML/CSS/JS

**理由**：

- 参数控件要按插件声明**动态生成**、处理链要能增删调序——这些"数据一变界面就得跟着变"的地方，手写同步最容易出错，也最难排查；
- 组件化天然实现"结构与逻辑分离"；
- Vite dev server + HMR 满足"改完即见"，构建只发生在交付环节。

**约束**：锁定 Vue 3 + 组合式 API，避免 AI 混用两代写法。

### D3 渲染器接口不依赖 UI 框架；内置实现用 Canvas 2D

**理由**：

- **接口**一旦绑框架，"渲染器可整块替换"就作废——换框架时所有渲染插件（含第三方）全部失效；
- 大数据必须用 Canvas / WebGL，而声明式模板**不参与绘制**，只是多一层包装；
- 内置实现用裸 Canvas 是出于**示范效应**：内置实现是第三方插件的模板。

**注意**：渲染器的**实现**内部可以用任何技术，只要求接口不变。

### D4 单条 WebSocket + JSON 信封

**理由**：实时功能需要**服务端主动推**，HTTP 做不到。统一信封让请求–响应与推送共用一套解析代码。

### D5 提取 → 滤波 → 聚合全部在后端

**理由**：滤波必须作用于**全量数据**。若前端先聚合再滤波，滤波就是在聚合后的数据上做的，**结果是错的**。

**配套**：跨进程接口只暴露"按视口 + 分辨率请求"，前端在结构上拿不到全量数据。

### D6 存储 V1 用 JSON；接口按"按 x 范围读取"定义

**理由**：

- JSON 能用记事本直接打开验证——这是"AI 生成的东西我能快速检查"的基础；
- 接口按**使用需求**而非文件格式抽象，将来加 SQLite / JSONL 只需新增一个实现模块，上层与插件零改动；
- 契约与存储分离，所以选错格式的代价很小。

**不提前换**：只有实测发现加载时间或体积确实成为问题，才换实现。

### D7 时间轴用数值毫秒

**理由**：分析只看波形，不看日历时间。数值可直接参与运算与绘制、体积小、彻底绕开时区与格式解析。

### D8 x 轴用开放式描述，不写死枚举

**理由**：核心只定义渲染器**必须理解**的最小语义集（`kind` + `scale`），其余作为描述信息或扩展区透传。
未知 `kind` 降级显示并明确标注，**不崩溃、不静默**。

### D9 可扩展 = 新增 + 组合 + 编排

**理由**：只做"插件"会在最后一步断掉——AI 写好了插件，但你得手工编辑配置文件才能启用，可扩展性等于没落地。

**验收**：从"文件放进目录"到"界面上能用"，中间无任何手工编辑步骤。

### D10 交付可打包为单个 exe，但打包不进开发流程

**理由**：开发循环必须是"改代码 → 运行 → 看结果"。

**两条硬要求**：

1. 打包后**插件机制必须仍然可用**（一票否决项）；
2. 打包不得影响架构——不得为打包方便牺牲模块化。

### D11 多语言：预留文案机制，当前只做简体中文

**理由**：文案集中在文案表，插件文案走 manifest 声明。
否则将来第三方插件的文案会散落在各自代码里，无法统一。

### D12 实时数据更新：本期不做，作为"持续模式数据源插件"预留

**理由**：实时 = 换数据源 + 渲染加追加。只需零成本地预留**接口形状**，不需要新增插件类别。
详见 [roadmap.md](roadmap.md)。

## 曾经否掉的方向（避免重走）

| 方案 | 为什么否掉 |
| --- | --- |
| 纯原生 HTML / CSS / JS，不用框架 | 界面复杂度（动态参数面板、处理链编辑）已越过"手写更省事"的阈值 |
| 用 SVG 画大数据 | 每个点一个 DOM 节点，到万级就明显吃力 |
| 前端先聚合再送回后端滤波 | 滤波会作用在聚合后的数据上，**结果是错的** |
| 渲染器**接口**绑定 Vue | 换框架时所有渲染插件作废 |
| C / C++ 或 C# WPF 原生开发 | 渲染可替换性与脚本插件机制都要从零造轮子，与"降低维护成本"的目标相反 |
| 为显示流畅做等间隔抽样 | 会抹掉尖峰与单点异常，而问题恰恰在那里 |
| V1 就实现存储格式自动探测 | 只有一种实现时探测是空转，等第二个格式出现再加 |
| 用 HTTP 轮询做数据更新 | 延迟与负载都差，且实时功能要推倒重做 |
