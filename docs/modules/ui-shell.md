# 模块：UI 外壳（UI Shell）

## 1. 一句话职责

面板、控件、对话框、状态提示——**画布容器外面**的一切。

**不负责**：画布内的图形（那是[渲染器](renderer.md)）、业务判断（那是[核心](core.md)）。

## 2. 代码位置

| 内容 | 路径 |
| --- | --- |
| 界面组件与布局 | `frontend/ui/App.vue`、`frontend/ui/components/`（FilePanel / ChartView / StatusBar） |
| 文案表 | `frontend/ui/strings.js` |
| 样式与 CSS 变量 | `frontend/ui/styles.css` |
| 入口 | `frontend/ui/main.js`、`frontend/index.html` |
| Vite 配置（root 即 `frontend/`） | `frontend/vite.config.js` |

> 目录按业务用途分（`ui/` `api/` `renderers/`），不套一层 `src/`。
> 起法见 [frontend/README.md](../../frontend/README.md)。

## 3. 对外接口

无对外接口。它通过[通信客户端](api-client.md)与后端交互。

## 4. 依赖规则

| | |
| --- | --- |
| 可以依赖 | Vue、通信客户端 |
| **禁止依赖** | 后端代码、渲染器内部实现 |

## 5. 扩展点

界面布局调整属于本模块的**内部**改动，不应影响其他模块。

**插件相关界面一律由后端的声明生成**，本模块代码不动：

| 界面元素 | 数据来源 |
| --- | --- |
| 数据源插件下拉 | M2 `list_plugins` 里 `type: "source"` 的项 |
| 插件参数控件（文本 / 数字 / 下拉） | 插件的 `params` 声明（`type` 决定控件种类，`default` 决定初值） |
| 坏插件警告 | M2 的 `warnings` 字段 |
| 序列勾选列表与单位 | M3 摘要的 `series[]` |
| 文件浏览弹窗 | M18 `browse`：浏览器拿不到本机路径，列目录只能由后端提供 |
| 横轴标题、刻度格式、纵轴单位 | M3 摘要的 `axis` 与 `unit`，交给[渲染器](renderer.md)显示 |

> 这是 U2 验收方法（"新增一个界面面板，核心代码零改动"）的具体落点：
> 新增一个插件，界面代码改动应当是 **0 行**。

## 6. 本模块的硬规则

来自 [ARCHITECTURE.md](../ARCHITECTURE.md) §5：

1. **U1 不含业务逻辑**——只做"把状态渲染出来"和"把操作转成命令发出去"。
2. **U2 与核心只有两类消息**（命令 / 状态与事件）。
   - **验收方法：新增一个界面面板，核心代码应零改动。**
3. **U4 视觉值集中管理**（颜色、间距、字号 → CSS 变量）。
4. **U5 结构与逻辑分离**，不在逻辑代码里拼大段 HTML 字符串。
5. **U6 不得破坏"改完即见"的开发体验**（不得引入需要手动构建才能看到效果的做法）。

## 7. 已知的坑

| 坑 | 现象 | 应对 |
| --- | --- | --- |
| 在界面里做业务判断 | 改界面时碰到逻辑，牵一发动全身 | 判断一律放后端；界面只按收到的状态渲染 |
| 硬编码颜色 / 字号 | 改风格要满仓库找 | CSS 变量 |
| 参数控件写死 | 新增插件参数要改界面代码 | 按插件的参数声明**动态生成**控件 |
| 界面自己判断聚合状态 | 与后端不一致 | 后端在响应里带标志，界面只负责显示 |
| 界面缓存全量数据 | 内存暴涨，且绕过了分层 | 只缓存"有权获得"的数据（聚合结果） |
| dev server 只绑 `localhost` | Windows 上常绑到 `::1`，用 `127.0.0.1` 打不开 | `vite.config.js` 里显式 `host: '127.0.0.1'` |
| 面板之间互相传业务状态 | 加一个面板就要改另一个 | 状态放 App 一层，面板只收 props、只发事件 |
