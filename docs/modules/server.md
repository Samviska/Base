# 模块：通信服务（Server，后端侧）

## 1. 一句话职责

WebSocket 服务端：建连、收发消息、**按 `id` 配对请求与响应**、把命令交给[核心](core.md)。

**不负责**：业务逻辑（交给核心）、界面。

## 2. 代码位置

| 内容 | 路径（规划） |
| --- | --- |
| WebSocket 端点与消息分发 | `backend/server/` |
| HTTP 端点（仅加载页面与静态资源） | `backend/server/` |

## 3. 对外接口

- WebSocket 端点：收发 §[protocol.md](../protocol.md) 定义的消息
- HTTP 端点：页面与静态资源，**不承担数据请求**

## 4. 依赖规则

| | |
| --- | --- |
| 可以依赖 | 核心、契约（消息结构） |
| **禁止依赖** | 具体插件、界面 |

## 5. 扩展点

新增消息类型 = 登记类型清单 + 加处理分支。见 [protocol.md](../protocol.md)。

## 6. 本模块的硬规则

1. **不得在业务代码里临时拼装未登记的消息类型。**
2. **请求必须回同 `id` 的响应**。即使出错也要回（带错误信息）——
   反例：某条命令抛异常后没有响应，前端界面永远停在加载中。
3. 服务端主动事件使用**无 `id`** 消息。
4. **不得阻塞接收循环**：长任务要异步处理，否则将来的实时数据会被拖死。
5. 消息清单本身属于契约，变更按契约流程走。

## 7. 已知的坑

| 坑 | 现象 | 应对 |
| --- | --- | --- |
| 异常路径没有响应 | 前端一直等 | 所有分支（含异常）都要回响应 |
| 端口被占用 | 启动失败，报错难懂 | 明确报错并给出可换端口（待办 C3） |
| 前端不知道后端已就绪 | 首次连接被拒 | 就绪探测（待办 C4） |
| 同步处理慢命令 | 后续消息全部堵住 | 长任务异步化 |
