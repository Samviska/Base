# 模块：通信服务（Server，后端侧）

## 1. 一句话职责

WebSocket 服务端：建连、收发消息、**按 `id` 配对请求与响应**、把命令交给[核心](core.md)。

**不负责**：业务逻辑（交给核心）、界面。

## 2. 代码位置

| 内容 | 路径 |
| --- | --- |
| WebSocket 端点与信封收发 | `backend/server/app.py` |
| 启动入口 | `backend/server/__main__.py` |
| 用例（端到端，真连接） | `backend/tests/test_server.py` |

HTTP 端点（页面与静态资源）**尚未实现**：开发期前端由 Vite dev server 提供。

## 3. 对外接口

### 启动

```powershell
.venv\Scripts\python.exe -m backend.server                # ws://127.0.0.1:8765
.venv\Scripts\python.exe -m backend.server --port 8791    # 端口被占用时换一个
```

### 端点行为

| 时机 | 行为 |
| --- | --- |
| 连接建立 | 先发一条 **M1 `hello` 事件**（无 `id`），带 `protocol_version` 与 `backend_version`（读根目录 `VERSION`） |
| 收到请求 | 交给核心处理，回**同 `id`、同 `type`** 的响应信封 |
| 收到无法解析的 JSON | 记日志并忽略：连 `id` 都没有，配不了对也就回不了响应 |
| 收到没有 `id` 的消息 | 记日志并忽略（前端不应发事件方向的消息） |
| 端口被占用 | 启动失败并**明确提示换端口**；不自动换——前端必须预先知道端口（待办 C3） |
| 连接断开 | 该连接的会话与缓存随之丢弃（会话不跨连接） |

**不阻塞接收循环**：命令处理放在工作线程执行（`asyncio.to_thread`）。
一旦接收循环被 CPU 密集的聚合堵住，将来的实时数据就会在缓冲区里丢。

## 5. 扩展点

新增消息类型 = 登记类型清单 + 加处理分支。见 [protocol.md](../protocol.md)。

## 6. 本模块的硬规则

1. **不得在业务代码里临时拼装未登记的消息类型。**
2. **请求必须回同 `id` 的响应**。即使出错也要回（带错误信息）——
   反例：某条命令抛异常后没有响应，前端界面永远停在加载中。
3. 服务端主动事件使用**无 `id`** 消息。
4. **不得阻塞接收循环**：长任务要异步处理，否则将来的实时数据会被拖死。
5. 消息清单本身属于契约，变更按契约流程走。

## 7. 已知的坑

| 坑 | 现象 | 应对 |
| --- | --- | --- |
| 异常路径没有响应 | 前端一直等 | **已做**：`handle` 兜底捕获一切异常并回 `INTERNAL`，端到端用例覆盖 |
| 端口被占用 | 启动失败，报错难懂 | **已做明确报错**并提示 `--port`；自动换端口不做（C3 仍待定） |
| 前端不知道后端已就绪 | 首次连接被拒 | **待做**（C4）：`hello` 已发出，重连策略未定，属第 5 批 |
| 同步处理慢命令 | 后续消息全部堵住 | **已做**：命令跑在工作线程里，接收循环不受阻 |
