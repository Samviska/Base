# 嵌入式数据可视化平台

> 项目名与包名待定。本文档只写"是什么"和"从哪开始"，细节一律在 `docs/` 里。

---

## 解决什么问题

分析嵌入式传感器数据的传统做法是：手工粘进 Excel 画图，或让 AI 生成一次性脚本。
两者的共同问题是**没有结构**——数据源一变、要提取的特征一改，就得整份重写；
而且改动依赖一段长对话的上下文，换个会话就断片。

本项目要做到的：**核心稳定、契约固定、能力靠插件增长**。
新增一种日志格式、一种图形、一种滤波算法，代价都是"新增一个文件"，而不是"重写"。

---

## 核心设计原则

| 原则 | 含义 |
| --- | --- |
| **契约驱动** | 所有模块只通过数据契约通信，不传递内部对象 |
| **物理分层** | 前端 / 后端是不同进程、不同语言，违规在结构上不可能发生，而非"被要求不发生" |
| **插件优先** | 新增能力默认走插件；改核心必须给出书面理由 |
| **文档即接口** | 文档与代码目录一一对应，丢失对话上下文也能按文档维护 |
| **不做抽样** | 图形用来发现问题，绝不为了画得快而丢弃极值 |

## 目录结构

| 目录 | 放什么 |
| --- | --- |
| `docs/` | 全部文档。**入口是 `docs/README.md`** |
| `contract/` | 数据契约的语言中立权威定义（schema、示例、校验用例） |
| `backend/` | Python 后端：数据提取、滤波、聚合、存储、通信服务 |
| `frontend/` | Vue 前端：界面外壳、通信客户端、渲染器 |
| `plugins/` | 内置之外的数据源 / 滤波 / 渲染插件 |
| `scripts/` | 启动、构建、打包脚本 |

各目录与文档的对应关系，见 `docs/MODULES.md`。

## 首次使用（clone 后必做）

```powershell
python scripts/setup.py      # 启用 git 钩子
pip install jsonschema       # 契约校验依赖
```

> `core.hooksPath` 是**本地配置**，不随仓库分发。漏掉第一步不会有任何报错，
> 但**所有提交前检查都会静默失效**。
